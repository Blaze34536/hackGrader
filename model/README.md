# Model

This section details the process to get a custom model that is more accurate in determining whether or not a piece of code, or repository in hackGrader's use case, was generated by an AI model. The model uses qwen2.5-coder as a base since it is very capable in giving code a "goodness" score when predefined.

## Pre creating the model

The model does require some "generated" data to ensure that it maintains tool capabilities. The data should be present in the dataset.jsonl file but could be outdated. It is recommended to re-run the ```create_data.py``` script before attempting to create the model to ensure that the model trains properly.

```sh
cd model/

# sync the packages inside the model directory
uv sync

# run the data script
uv run src/create_data.py
```

## Creating the model

The model creation is split up into three parts:

1. Run the training script

```sh
uv run src/train.py
```

2. Convert the output from the training script to a .gguf model file

```sh
uv run python llama.cpp/convert_hf_to_gguf.py qwen3_ai_detector_merged --outfile ai_detector_q8.gguf --outtype q8_0
```

3. Build and register the model with [ollama](https://ollama.com)

```sh
ollama create hackgrader -f Modelfile
```

After the model has been registered it is ready to be used and selected as the default model for hackGrader.
